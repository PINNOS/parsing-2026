# No-code (n8n): заметки

## Что реализовано в workflow.json
- Два триггера: Schedule Trigger (ежедневно 06:00 UTC) и Manual Trigger
  «Ручной запуск (тест)» — для проверки без ожидания расписания.
- «План сбора (15 страниц)» (Code): строит 15 URL по 5 страниц на каждый из
  трёх доменов, каждому элементу проставляет поле `wait_ms`.
- «Запрос страницы (пауза 2 с, повторы 429/5xx)» (HTTP Request): встроенная
  опция **Batching** (`batchSize: 1`, `batchInterval: 2000`) даёт
  последовательную паузу между запросами без узла цикла; `retryOnFail`
  с 3 попытками и задержкой 2000 мс. UA задан заголовком
  `StudentScraperBot/1.0 (+https://github.com/PINNOS/parsing)`.
- «Разбор записей» (Code): считает записи регулярным выражением по классам
  `product_pod|quote|product-item`; домен и URL берутся из плана через
  `pairedItem`, а не из тела ответа.
- «Собрать результат в JSONL» (Code): собирает все страницы в один NDJSON и
  отдаёт его как binary (inline base64), затем «Результат (JSONL)»
  (Write Binary File) пишет `/data/nocode/nocode_result.jsonl`.
- «Собрать инциденты в JSONL»: страницы с кодом ≠ 200 уходят в
  `/data/nocode/nocode_alerts_incidents.jsonl`.
- «Проверка: записей меньше 30» (IF): при низком выходе пишется
  `/data/nocode/nocode_alerts.jsonl`; на здоровом прогоне ветка не срабатывает.

Почему без узла «Loop Over Items»: в n8n 2.43.7 узел `splitInBatches` (v3) в
режиме CLI-исполнения `n8n execute` делает ровно одну итерацию и сразу отдаёт
ветку done, поэтому цикл не выполнялся. Заменён на встроенный Batching узла
HTTP Request — он даёт ту же последовательную паузу и работает в любом режиме.

## Что не удалось (см. раздел 17 блокнота)
- Token bucket и джиттер: узлами не выражаются, пауза фиксирована.
- Независимость доменов: один последовательный поток запросов сериализует домены.
- Retry по классам ошибок и Retry-After: встроенный Retry On Fail повторяет всё подряд.
- Предохранитель-FSM: собран только «остановить и оповестить».
- Условные запросы (ETag): требуют состояния между запусками, не реализованы.
- Распределённый лимит: один сценарий n8n = один процесс.

## Оценка стоимости (в выполнениях и запросах, не в валюте)
| Показатель | Значение |
|---|---|
| Запросов на запуск | 15 |
| Записей на запуск | 210 (при полном плане) |
| Запусков в сутки | 1 |
| Выполнений в месяц | ~30 |
| Запросов в месяц | ~465 |
| При расписании каждые 15 минут | ~2 880 выполнений/мес |

Облачные тарифы считают выполнения и имеют лимит (порядка 2 500 в базовом тарифе),
поэтому 15-минутный режим потребует следующего тарифа. Self-hosted (наш Docker-стенд)
выполнения не ограничивает.

«Execute workflow» (или Manual Trigger для теста).
